# 지금 돌아가는 시스템 — 전체 흐름 한 번에 읽기

> **이 문서의 목적**: 화물 서열 하나를 넣으면 최종 후보가 나올 때까지, **언제 어떤 모델이
> 불리고 어떤 게이트가 걸리는지**를 순서대로 적는다. 왜 그렇게 설계했는지(근거·실험)는
> `docs/experiments.md` 에 있고, 여기는 **지금 코드가 실제로 하는 일**만 쓴다.
> 코드와 어긋나면 **코드가 맞다** — 확인 위치를 각 절 끝에 `파일:줄` 로 달았다.
> 기준 커밋 `c0bd09d` (2026-11-16).

## 0. 30초 요약

```
화물 1개 (예: GSNKGAIIGLM, 11aa)
   ↓
[LLM 설계자] 라이브러리에서 고르고 → 잔기를 직접 편집하고 → 스스로 "끝"을 선언
   ↓   (매 후보마다 결정론 채점기 6종이 돌아 숫자 한 줄을 만든다)
[LLM 심사자] 다른 컨텍스트에서 적대적으로 검증 → APPROVE / REVISE
   ↓
[결정론 게이트 7개] LLM 판정을 **덮어쓴다** (여기가 실제 판정)
   ↓
[복구] 탈락한 제출은 이 세션이 이미 채점해 본 최고 후보로 **바꿔서** 제시
   ↓
최종 후보 1개 + 위험 축 4개 + 참고 수치(BBB·구조) + 원장 기록
```

핵심은 셋이다.
1. **LLM 은 설계하고 제안할 뿐, 합격을 결정하지 못한다.** 판정은 결정론 게이트가 한다.
2. **BBB 점수는 순위에 안 쓴다.** 보고치다(이유는 §6).
3. **"좋다"고 말할 수 있는 근거는 문헌 인용 하나뿐이다.** 나머지 축은 전부 "나쁘지 않다"만 잰다.

## 3. 한 번 돌릴 때 실제로 일어나는 일 (시간 순)

### ⓪ 준비 — LLM 호출 **전**

**원장 읽기.** `.cache/ledger/<화물>.json` 에서 지난 세션들의 상위 후보와 **실패 사유**를
불러와 첫 프롬프트에 붙인다. "이미 아는 것을 다시 내는 건 가치 없다, 이 바닥을 넘어라"로
못박는다 — 원장은 목표가 아니라 **하한**이다.
⚠️ 벤치마크·애블레이션은 `use_ledger=False` 로 **끈다**(콜드 세션과 비교 불가해지므로).

**도달 가능 집합 계산.** 라이브러리 156 조합을 **에이전트와 똑같은 채점기로** 전수 채점해
"이 문제에서 실제로 달성 가능한 최선"을 만든다. LLM 0회, 디스크 캐시.
화물 A 기준: **156 → 132(조성 필터 통과) → 89(후보 자격) → 전선 23 → `front_top` 5**.
이게 없으면 심사자가 *절대적 이상*과 비교해서 승인 가능 영역이 비어버린다(실측: 130조합 중 0개).

📁 `core/ledger.py:298` · `core/optimizer_agent.py:341-479`

### ① PLAN — 도구 없이 전략만

LLM 에게 도구를 **빼고** 물어본다: "어떤 방향을 먼저 탐색할 건지 2~3문장." 선언을 먼저
받아두면 나중에 결과와 대조할 수 있다.

### ② ACT 루프 — 최대 10스텝 (+심사 재설계용 1스텝)

매 스텝에서 LLM 은 도구 4개 중 하나를 부른다.

**ⓐ `evaluate_candidates` — 고르기 전용**
라이브러리 **원본 조합만** 받는다(한 번에 최대 24개). 한 잔기라도 편집된 서열을 넣으면
**채점을 거부하고 되돌려보낸다.** 이유: 옛 코드가 임의 서열을 받아줘서 LLM 이 평가 도구를
설계 통로로 전용했고, 그러면 "설계 도구의 기여"를 **측정 자체가 불가능**해진다.
거부 횟수는 계측값으로 센다.

**ⓑ `design_candidate` — 만들기 전용**
셔틀·링커를 자유 편집한 서열을 채점한다. **가설·예측을 반드시 적어야** 호출된다
(필수 인자). 채점 후 LLM 에게 *"네 예측과 실제 점수를 대조하라"*를 강제로 돌려준다.
링커 제약은 **표준 20 아미노산 · 최대 17aa** 둘뿐이다. 응답에 두 가지가 자동으로 붙는다:
- **근거 상속 판정** — 이 설계체가 어느 셔틀의 등급을 물려받는지 그 자리에서 알려준다.
- **접합부 검사** — `화물 끝 ⊕ 링커 ⊕ 셔틀 시작`에 새로 생긴 liability 모티프를
  결정론으로 검출해 알려준다. 이게 **링커가 고칠 수 있는 유일한 축**이다.

**ⓒ `optimize_developability` — 결정론 GA 도구**
셔틀 하나를 받아 유전 알고리즘(`rounds=25 × pop=24`, 시드 2022)으로 변이체 전선을 만든다.
목적은 **3축 동시 최소화**(liability 개수 · 응집 핫스팟 · 불안정성)이고, 제약이 셋이다:
`rmt_sim ≥ 0.85`(기능 보존) · **문헌 보존 위치 동결** · **`|off − 시드 off| ≤ 0.05`**(양측 밴드).
전선 상위 6개를 **실제로 채점해** 러닝 베스트·원장·래칫에 넣는다(옛 코드는 텍스트로만
보여줘서 결과가 결정에 닿지 않았다).

**ⓓ `finish` — 자기 종료 선언**
LLM 이 스스로 수렴했다고 판단하면 부른다. 10스텝은 **안전 상한**이고 보통 5~6에 끝난다.

> **매 후보가 받는 숫자 한 줄** — 도구 ⓐⓑⓒ 전부 같은 채점 경로를 쓴다:
> deepB3P(융합 연결부위 + 셔틀 단독) · ToxinPred3(전체 서열) · 불안정성 · liability 개수 ·
> 응집 핫스팟(설계 모듈) · off-target(셔틀) · 순전하 · 용해도 · 근거 등급(+상속 부모·유사도) ·
> RMT/CPP 기전 · 융합 보존도.
> 🔴 **deepB3P 는 50aa 상한**이 있어서, 구성체가 50aa 를 넘으면 **화물을 잘라내고
> 링커+셔틀만** 넣는다. 독성은 항상 **전체 서열**로 잰다.

📁 `core/optimizer_agent_gemini.py:183-345` (도구) · `core/optimizer_agent.py:218-330` (채점)

### ③ 러닝 베스트 — 세션 내 기억

채점된 모든 행 중 **후보 자격이 있는 것**만 모아 결정론 정렬키로 최고치를 들고 간다.
CPP 는 따로 `best_cpp` 에 보관(보고용). 이 값이 나중에 **래칫 게이트와 복구**에 쓰인다.

### ④ CRITIC — 독립 심사 (LLM 2차)

`finish` 가 불리면 제출 후보를 채점하고, **완전히 다른 컨텍스트**에서 심사자를 띄운다.
심사자가 받는 것: 제출 후보의 전체 지표 + **도달 가능 집합**(전선·최상위 그룹·비교군 기준선).

심사자에게 명시적으로 금지한 것 둘:
- "절대적 이상과 비교하지 마라" → 기준은 **달성 가능한 최선**이다.
- 🔴 **"BBB 점수가 낮다는 이유로 REVISE 하지 마라"** → 탈락 사유가 아니다.

판정은 3단계다: `APPROVE` / `APPROVE_WITH_LIMITS`(정상적인 승인 형태) / `REVISE`.
애매하면 REVISE 가 아니라 `APPROVE_WITH_LIMITS` + 한계 명시로 가게 했다.

📁 `core/optimizer_agent_gemini.py:653-760`

## 4. 🔴 결정론 게이트 7개 — **여기가 실제 판정이다**

심사 LLM 이 뭐라고 했든, 아래 게이트가 걸리면 **덮어쓴다**. 위에서부터 차례로 보고
하나라도 걸리면 `REVISE`.

| # | 게이트 | 조건 | 왜 |
|---|---|---|---|
| **①** | **독성** | ToxinPred3 점수 **> 0.38** | 유일한 안전성 하드 게이트 |
| **②** | **근거 상속** | 설계체가 가장 닮은 라이브러리 셔틀과 **유사도 < 0.70** → 등급 상속 실패(미등재) | 인용 없는 서열은 후보가 될 수 없다. 조성 쌓기·homopolymer·무작위가 전부 여기서 걸린다 |
| **③** | **등급 D** | 물려받은 등급이 **D**(= BBB 단독 근거 없음) | Tet1 이 여기 온다 |
| **④** | **비교군** | 제출이 **CPP** 이고, 게이트를 통과한 **RMT 후보가 하나라도 실재** | 비교군을 결과로 확정할 이유가 없다 |
| **⑤** | **근거 하향** | 비지배여도 **달성 가능한 최상위 근거 그룹보다 낮은 그룹**을 골랐다 | 위험 축이 조금 좋다는 이유로 근거가 약한 셔틀을 고를 수 없다 — 위험 축은 "좋음"을 재지 않는다 |
| **⑥** | **지배** | `front_top` 의 어떤 후보가 **모든 축에서** 제출을 지배 | 트레이드오프가 아니라 그냥 못한 선택 |
| **⑦** | **래칫** | **이 세션이 이미 채점해 본** 러닝 베스트가 제출을 지배 | 더 좋은 걸 손에 쥐고 더 나쁜 걸 확정하는 것 금지. 탐색의 상방은 살리고 하방만 자른다 |

**게이트 ①②가 "하드"이고 ④⑤⑥⑦은 "달성 가능한 대안이 실재하느냐"를 묻는다.** 그래서
⑥⑦은 절대 기준이 아니라 **상대 기준**이고, 걸릴 때 항상 **대안을 지목**한다.

### 재설계 기회는 1회
`REVISE` 가 나오면 심사 반박을 그대로 LLM 에 돌려주고 **여분 스텝 1개**를 준다.
그 기회를 쓰고도 안 되면 ↓ 복구로 넘어간다.

📁 `core/optimizer_agent_gemini.py:764-850`

## 5. 복구 — 검출만으로는 못 고친다

게이트는 위반을 **검출**해서 REVISE 를 낼 뿐이고, 재설계 기회를 소진하면 그 나쁜 후보가
그대로 최종이 된다(실측: 옛 순서 게이트 때 2세션 모두 승인 0건, 래칫 때 4세션 중 3세션).
그래서 **검출 + 복구를 한 쌍으로** 둔다 — 탈락한 제출을 **이 세션이 이미 채점해 본
최고 후보로 바꿔서** 제시하고, 그 사실을 보고서에 적는다.

| 상황 | 복구 동작 |
|---|---|
| 제출이 **CPP** | 후보군 러닝 베스트로 교체 (없으면 "최종 후보 없음"으로 정직하게 종료) |
| 제출이 **미등재/등급 D** | 러닝 베스트로 교체 |
| 러닝 베스트가 제출을 **지배** | 러닝 베스트로 교체 |

🔴 **교체가 일어나면 교체된 후보로 심사를 다시 돌린다** — 이전 판정은 버린 후보의 것이니까.

## 6. 순위 — 어떻게 줄 세우나

**사전식(lexicographic) + Pareto**, 두 단계다.

### 1단계 — 문헌 근거 그룹 (앞 단계가 뒤를 지배한다)
```
근거 있음(A·B)  >  주의(C)  >  근거 없음(D) ✗자격  >  미등재 ✗자격
```

### 2단계 — 같은 그룹 안에서 **위험 축 4개 Pareto** (전부 작을수록 좋음, 서로 우선순위 없음)

| 축 | 무엇을 재나 | 어느 범위 |
|---|---|---|
| `dev_liab` | liability 모티프 **개수** | 전체 구성체 |
| 불안정성 | Guruprasad 지수 **< 40 이면 0, 아니면 1** (이진) | 전체 구성체 |
| `sel_off` | off-target 위험 (전하밀도 + 소수성 − RMT 유사도) | **셔틀만** |
| `dev_agg_hot` | AGGRESCAN a3v 창 5aa **국소 최대** | **설계 모듈**(링커+셔틀) |

범위를 왜 저렇게 잘랐나: **우리가 바꿀 수 있는 모듈을 잰다.** 화물은 고정이고, 화물
`GSNKGAIIGLM` 은 `AIIGLM` 때문에 자체 핫스팟이 0.80 이라 전체로 재면 셔틀 12종이 전부
0.80 으로 묶여 **축이 죽는다**. 불안정성을 이진으로 두는 것도 같은 이유 — 연속으로 두면
"길이를 늘려 숫자만 깎기"가 가장 싼 해가 된다.

### 🔴 순위에 **안 들어가는** 것

| | 왜 빠졌나 |
|---|---|
| **BBB 점수 (deepB3P)** | 셔틀 간·링커 간 순위를 매길 수 없음이 실측으로 확인됐다. **보고치로만** 적는다 |
| **구조 노출도 (ESMFold)** | 도구에서 뺐다 — 애블레이션에서 자기 고유 축에서조차 기여가 없었고 호출당 ~10초 + 공개 API 장애 위험만 더했다. 최종 1건 참고 보고로만 남겼다 |
| **순전하 · 용해도 · 지방족 지수 · 융합 보존도** | 계산해서 **보고**하지만 순위 축이 아니다 |
| **스칼라 유효점수** | `BBB − 0.25 × off` 식은 폐지했다. 되살리지 말 것 |

⚠️ **"비지배 = 더 좋다"가 아니다.** Pareto 비지배는 **교환관계**다. 개선된 축과 악화된
축을 항상 같은 문장에 적는다.

## 7. 마무리 — 최종 산출

1. **구조 증거(ESMFold)** — 최종 후보 **1건만** 공개 API 로 접어 셔틀 표면 노출도를 본다.
   실패하면 **조용히 건너뛴다**(참고 근거라 결과를 막지 않는다). 디스크 캐시.
2. **비교군 참고선** — CPP 최고치를 보고서 각주로 남긴다. 결과 카드에는 올리지 않는다.
3. **원장 기록** — 이번 세션의 채점 행 전부 + 최종 선택 + **실패 사유**를 화물별 파일에
   쌓는다(승자 60 · 실패 40 상한, 실패는 따로 보존). 다음 세션의 바닥이 된다.
4. **UI 출력** — 포디움 상위 3 + 심사 카드(승인/미승인 + 반박 전문) + 과정 기록.
   미승인으로 끝나면 **실패 진단 + 대안 권고**를 붙인다(정직한 미승인).

## 9. ⚠️ 알고 있는 구멍 — 흐름을 읽을 때 같이 봐야 하는 것

이 시스템의 약한 자리를 **측정해서** 알고 있다. 흐름 설명만 읽으면 더 단단해 보이므로
같이 적는다. (상세 수치는 `docs/논문개요.md` §6)

1. 🔴 **게이트 ②(근거 상속)는 기능 보존을 대리하지 못한다.** 재는 것은 "얼마나 많이
   고쳤나"이고 "무엇을 고쳤나"가 아니다 — 무작위 **단일 치환**에서 기능이 무너진 65개가
   65개 전부 등급을 받았다(검출률 **0.0%**). 그리고 LLM 과 GA 는 모두 **2~3개 치환**
   구간에서 일한다. **게이트가 가장 약한 구간이 시스템이 실제로 있는 구간이다.**
2. 🔴 **문헌 보존 위치(핀)가 등록된 셔틀은 12종 중 1종**(Angiopep-2 의 K10·K15)뿐이다.

   기능 하한이 없다. 셔틀 쪽 유일한 통제가 게이트 ②이고, 그게 위 1번이다.

    A 팔(GA)은 매 실행 재채점된다 → **축 정의가 바뀌면 두 팔의 단위가 갈라진다.** §68 에서
    `dev_liab` 의 응집 임계 가산을 빼자 A 팔만 전부 −1 이 되어 **A 팔에 liability 1개의
    공짜 우위**가 생길 뻔했다. 🔴 이 파일은 §38-1 때 같은 일을 겪고 **경고문을 적어 두었는데
    그 경고문이 다음 변경을 막지 못했다.** 처방: 기록은 `(링커, 셔틀, 평가 횟수, 세션)`
    만 보존하고 **축은 매 실행 현행 코드로 재계산**(`_renorm`)하며, 기록과 어긋나면 그
    차이를 출력한다. 📌 일반화 — **기록에 측정값을 적지 말고 입력을 적는다.**

14. 🆕 ⚠️ **순위 축 4개 중 3개가 화물을 보지 않는다**(2026-11-17 §69). `sel_off` 는 셔틀
    단독, `dev_agg_hot` 는 설계모듈(링커+셔틀)이라 **정의상** 화물 불변이고, `dev_liab` 는

    전선 셔틀 7종과 대표 설계가 **그대로**이고 4축 벡터가 동일한 조합이 **141/156(90.4%)**
